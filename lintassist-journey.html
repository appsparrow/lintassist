The Spark & The First Wall

The Idea
Idea
What if designers could audit any screen with AI?
The insight was simple and sharp: designers audit screens every day — checking heuristics, scanning for accessibility failures, spotting hierarchy problems. It's tedious, inconsistent, and slow. Claude can do this in seconds. The question was whether it could be packaged into something a real designer would actually use in their workflow.

Build

Built a web app that accepts screenshots and runs them through Claude with a structured UX audit prompt — scoring across Nielsen heuristics, Gestalt, typography, accessibility, and more. Simultaneously built a Figma plugin that could export any selected frame directly to the same analysis pipeline. It worked beautifully on local.

Hit 1
CORS Wall
Problem
Figma's sandbox blocks direct API calls — Origin: null
The Figma plugin sandbox sets Origin: null on all requests. Anthropic's API rejects this. The plugin couldn't call Claude at all. This is a known, unfixable browser security constraint.
The fix Cloudflare Worker as a CORS proxy. Worker receives the request, strips the null origin, forwards to Anthropic with the API key. Deployed in 10 minutes. Problem permanently solved.

Critical
API Key Problem
Problem
"Users shouldn't see the Anthropic API key"
The original architecture had users supply their own API key. For a consumer subscription product, this is a non-starter — you can't charge $15/month and also make people get their own API key. The key had to be completely hidden. This required a full backend redesign: the Worker becomes the gatekeeper, tokens replace API keys, and every request is authorised server-side.

III
Building the Backend
From "edit a file to add users" to a real database
v1
Bad Idea First
Identified Problem
"Adding subscribers by editing code is terrible"
The first SaaS worker stored subscribers directly in the JavaScript file — a hardcoded object. Adding a paying customer meant editing the code and redeploying. One typo breaks the entire API for all users. Siva spotted this immediately: "I should maintain subscribers somewhere else." Supabase was considered. Then: "Or even better, D1 from Cloudflare since we're already there and it has a generous free limit."
v2
D1 Database
Shipped
Cloudflare D1 — SQL right next to the Worker
Migrated subscribers and usage tracking to Cloudflare D1 — a SQLite database that lives in the same edge network as the Worker. Zero latency, free up to 5GB, proper SQL. The Worker went from "a JS file with a hardcoded object" to a real API with two tables, monthly usage resets, and atomic credit increments.

usage (token, month_key, count)
Debug
Two Errors
Problems
CORS null origin + "no such table: subscribers"
Two runtime bugs hit in quick succession. The CORS error was because opening admin.html from the filesystem gives Origin: null — the same sandbox problem as Figma. Fix: serve via python3 -m http.server 8080 or deploy to Pages. The D1 error was because --remote was missing from the schema command — tables were created in a local SQLite file, not the actual Cloudflare database.
The correct command wrangler d1 execute ux-audit-db --remote --file=schema.sql

IV
Product Thinking
The subtle paywall. One token, everywhere.
UX
Soft Paywall
Product Decision
Show them the value first, then ask for money
Removed the big pricing section from the main page. Replaced it with two anonymous free audits — shown as two dots in a strip. No account, no friction, no credit card. After the second audit completes and the report is visible, the paywall slides in below. They see the value first, then the ask. Three plan cards: Starter $7 · Pro $15 (featured) · Credits $3.
The moment Audit completes → report renders → 1.4 second delay → paywall slides in below → "Like what you see? Keep the momentum going."
Key
Token System
Shipped
One token. Web app + Figma plugin. Same backend.
The token system means a user subscribes once and gets access everywhere. They paste the same tok_abc123 into the web app and into the Figma plugin's settings panel. Both call the same Worker endpoint. The same D1 database tracks usage across both. No separate auth systems, no duplication of limits.
shared x-ux-token header free_ anonymous tokens unified D1 usage tracking
Bug
Plugin Frozen
Problem
Plugin loaded, looked perfect — nothing clickable
Siva imported the plugin into Figma. It rendered. The UI looked great. But nothing worked — not the token button, not frame selection, not the chips. Complete freeze. The root cause: localStorage throws a security error in Figma's sandboxed iframe. The error fired before any event listeners attached. The whole JS crashed silently.
The fix Replace all localStorage with figma.clientStorage.
Storage now lives in code.js (the sandbox), not the iframe.
code.js sends token + freeUsed to ui.html via postMessage on init.
figma.clientStorage postMessage init pattern Zero localStorage in ui.html

What This Build Taught
Lessons in human-led, AI-assisted product building
01
Every error is a product decision
The CORS error led to Cloudflare Workers. Workers led to D1. D1 led to a proper admin system. The bugs weren't detours — they were the route.
02
Stay in one cloud
Worker + D1 + Pages all on Cloudflare means zero cross-cloud latency, one billing account, one deployment system. Simplicity compounds.
03
The soft paywall beats the hard wall
Show the report first. Then the ask. "Like it? Keep the momentum going." converts better than a gate. Users who've seen value are already sold.
04
One token, all surfaces
The decision to make the same token work on web and Figma plugin made the product feel unified. One subscription, everywhere. That's a product principle, not just an implementation detail.
05
Sandbox environments lie
Figma's iframe and file:// both set Origin: null. localStorage throws silently. Always test in the actual target environment, not local. --remote flag on D1 commands too.
06
Product instinct before perfect code
Siva caught the "editing code to add subscribers" problem immediately. That's not a technical skill — it's product intuition. The best systems are designed by people who will operate them.
